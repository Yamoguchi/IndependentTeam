## Исправлено

| Область | Ошибка прежнего кода | Исправление и проверка |
|---|---|---|
| Harness-отчёт | Код обязательно требовал процесс-предок JiuwenSwarm. Условие допускает переменные JIUWENSWARM_* **или** процесс openJiuwen/JiuwenSwarm. | Удалено лишнее обязательное условие; добавлено распознавание процессов openJiuwen. Тест допускает реальные унаследованные переменные без видимого предка. Маркеры не создаются сборщиком. |
| OpenRouter | Проверялось окружение, переданное subprocess, но не повторная загрузка dotenv в приложении. JiuwenSwarm вызывает загрузчик с override=True, что могло затереть ключ, особенно переданный через окружение. | Настройки разрешаются перед запуском; повторная загрузка dotenv в дочерних процессах отключается штатной переменной python-dotenv. Тест запускает настоящий загрузчик JiuwenSwarm в отдельном процессе с фиктивными ключами, без вызова модели. |
| HTTP 429 | HTTPStatusError перехватывался вокруг вызова инструмента. Но MCP SDK 1.30 выбрасывает ошибку HTTP в фоновой задаче, что может завершить transport. | Клиентский адаптер преобразует явный HTTP 429 в локальную JSON-RPC-ошибку с Retry-After, сохраняя сессию. Повтор выполняет Protocol с новым challenge и новой подписью. Локальный HTTP-тест реально возвращает 429 и проверяет разные nonce до и после повтора. Timeout мутации автоматически не повторяется. |
| Подтверждение результата | Проверялось наличие дат, но не их формат; heartbeat не сверял версию ответа. | Добавлена валидация UTC ISO 8601 с Z и ожидаемой версии. При подтверждённом собственном ID его можно использовать для корректного завершения даже при неверной дате анкеты. |
| Диагностика | Ответ после неудачной проверки мог остаться только в памяти. | Собственный ответ сохраняется в приватном журнале session_failed с удалением анкеты и чувствительных полей. |
| Лишнее ограничение | Имя/версия ограничивались локально 128 символами, хотя страница этого не задаёт. | Недокументированный лимит убран; strip и сохранение регистра остаются. |
| Инструкция запуска | Короткий --once предлагался как основной пример. | Основной пример теперь сохраняет присутствие агента во время работы. --once остаётся необязательным коротким сеансом; его выполнение не гарантирует зачёт квалификации. |

## Сверено с условием

| Требование | Реализация |
|---|---|
| Четыре инструмента MCP, без организаторских read API | create_registration_challenge, register_agent, heartbeat, deregister_agent; discovery проверяет их наличие. |
| Первичный registration challenge без name/version/registration_id | Передаётся ровно `{}`. |
| Отдельный Ed25519 SSH-ключ | OpenSSH private key, публичный ssh-ed25519, права приватного ключа 0600; повторная генерация не перезаписывает ключ. |
| Анкета из человека, 2–3 участника | Чтение JSON, строгие типы/поля/форматы/лимиты; значения не генерируются. |
| Явное согласие | accepted=true не выставляется программой. Перед отправкой требуется актуальная версия согласия и подтверждённый отправителем хеш текста. |
| Digest исходной анкеты до trim | ensure_ascii=False, sort_keys=True, separators=(',', ':'), allow_nan=False; порядок участников сохранён. |
| Подпись UTF-8 без добавленного перевода строки | Подписывается nonce:name:version:report_digest:team-v1:team_digest; имена/версия strip без изменения регистра. |
| Raw Ed25519 разрешён | 64 байта подписи кодируются base64. Использовать ssh-keygen -Y sign не обязательно: raw-формат прямо разрешён страницей. |
| Новый ID из собственного ответа | Проверяются аттестация, подпись, fingerprint и 32-hex ID; ID живёт в текущем процессе. |
| Повторный чек-ин без анкеты | --preserve-team опускает team и суффикс team-v1; он работает только если анкета уже сохранена у организаторов. |
| Heartbeat примерно каждые 30 минут | Интервал 1800 секунд по умолчанию, новый challenge на каждую операцию. |
| Подпись точного поля message для операций | Подписывается исходная строка из ответа; разбор JSON используется только для проверки принадлежности, не для повторной сериализации подписи. |
| Завершение только со своим ID и без version | deregister_agent получает собственные name/ID/nonce/proof, без version. |
| Ключ и анкета остаются после deregister | Отражено в README; deregister не отменяет согласие и не удаляет анкету. |
| Retry-After, ограниченный backoff, новый nonce | Не более пяти попыток явной перегрузки; ожидание Retry-After/backoff + jitter. |

## Дополнительные решения клиента, не требования организаторов

- `--consent-sha256` — наша локальная защита от отправки с устаревшей формулировкой. Это не обязательное поле MCP-протокола.
- `--once`, локальный lock, журнал и команды runtime-init/runtime-start — удобства этого проекта.
- Сборщик `scripts/collect_harness_report.py` написан нами по опубликованному формату. Это не найденный официальный файл из репозитория организаторов. Он собирает унаследованные переменные-пути и реальные процессы, затем вычисляет SHA-256 точной JSON-строки.
- Наличие маркеров — проверка формата отчёта, а не криптографическое доказательство настоящего harness. Выполнять сбор необходимо через shell самого агента, не подделывая переменные или процессы.

## Проверки и оставшаяся неопределённость

Пройдены **25 тестов**, включая локальный MCP/HTTP, независимую проверку Ed25519,
неизменность исходного JSON, чужой/устаревший ID, реальный HTTP 429, отсутствие
повтора после timeout, UTC-даты, версию heartbeat и загрузчик dotenv JiuwenSwarm.
Линтер и форматирование проверены.

Сервер конкурса не получал анкету в ходе этой сверки. Полный живой цикл с настоящей
командой, реальным агентом и моделью не выполнялся. Поэтому соответствие опубликованному
формату и локальные тесты не равнозначны подтверждённой регистрации или зачёту
квалификации организаторами. Точное расположение полей успешного ответа проверено
по описанию страницы и поддерживаемым вариантам, но не по ответу живой регистрации.
