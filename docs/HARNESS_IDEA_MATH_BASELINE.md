# Идея для будущего эксперимента с режимом B

Предварительный вариант — использовать `baseline` для задач `math`, а режим `B` для `coding`, `search` и `data_analysis`. Идея отложена. Работу продолжаем по [согласованному плану](HARNESS_IMPLEMENTATION_PROMPTS.md).

На одинаковых 14 задачах `baseline` набрал 33/33 балла, `A` и `B` набрали по 31/33. Переход `A → B` снизил расход на 2,9% при равных баллах. Разницу с `baseline` дала одна задача, `math_0001`. Два дополнительных варианта режима `B` убрали цикл из 20 шагов, но на полном пилоте модель всё равно сдала неверный результат этой задачи. Это наблюдение по одной задаче, устойчивость гибридного варианта ещё предстоит измерить. [Первый замер](../logs/experiments/stage-04-live.rShJre/comparison-report.md) · [Контрольные прогоны](../logs/experiments/stage-04-ablation.z3hxpr/ablation-report.md)

Если вернёмся к идее, проверить её отдельным режимом. Повторить пилот на тех же 14 входах с одинаковыми образом, моделью и лимитом, затем независимо оценить ответы. Условие для прогона на 100 задачах — 33/33 балла и меньший расход, чем у `baseline`, на сопоставимых входах с полным учётом токенов.
